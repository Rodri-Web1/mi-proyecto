Guía Explicativa

Este documento justifica las etiquetas semánticas elegidas para index.html y describe, paso a paso, la estrategia CSS aplicada para lograr fluidez visual sin usar Flexbox, CSS Grid ni Media Queries, tal como exige la actividad "Desafío Práctico: Programación Web I".

1. Justificación de las etiquetas semánticas

Se evitó el uso de <div> genéricos siempre que existió una etiqueta con significado propio para ese bloque de contenido.

<header>
Se eligió para el encabezado porque agrupa la identidad del sitio (el nombre) y la navegación principal: es exactamente lo que HTML5 define como el propósito de esta etiqueta, y evita usar un <div id="header"> sin significado.
<nav>
El menú de anclas que enlaza a cada sección es, por definición, un bloque de navegación. Usar <nav> permite además que lectores de pantalla lo anuncien como tal y lo salten fácilmente.
<main>
Envuelve todo el contenido único de la página (sin repetir cabecera ni pie). Solo puede existir un <main> por documento, lo cual ayuda a la accesibilidad y al SEO.
<section>
Cada eje temático del podcast (Computación Cuántica, Constanza, Nuevo Contrato Social...) es un bloque temático propio con su encabezado <h2>, por lo que corresponde usar <section> en lugar de <div>.
<article>
Cada tarjeta dentro de una sección (por ejemplo, "La Regla de los Cuatro Nueves") tiene sentido leída de forma aislada, como una pequeña nota autocontenida: por eso se usa <article> en vez de <div class="tarjeta"> sin más.
<figure> y <figcaption>
La galería asocia cada imagen con su descripción. <figure> declara ese vínculo explícitamente y <figcaption> marca el texto como el pie de esa imagen concreta.
<table>, <thead>, <tbody>, <th>
El reparto del "nuevo contrato social" en tres tercios es, literalmente, una tabla de datos con relación fila/columna, no una lista decorativa: se usó <table> con scope="col" y scope="row" para que los lectores de pantalla asocien cada celda con su encabezado correcto.
<video> y <source>
Se usaron para incrustar el video propio del proyecto, tal como permite la Fase 2 de la actividad ("<iframe> de YouTube o la etiqueta nativa <video>"). source declara el archivo y su tipo MIME, y el texto dentro de la etiqueta sirve como respaldo accesible si el navegador no admite video en HTML5. El código con <iframe> de YouTube queda documentado, comentado, como alternativa en el propio index.html.
<blockquote> y <footer>
La cita textual de cierre usa <blockquote> porque es una cita literal de Latorre, con un <footer> interno para atribuir la autoría, distinto del <footer> general de la página (que es el pie del sitio completo).
<dl>, <dt>, <dd>
El glosario de etiquetas es, conceptualmente, una lista de términos y sus definiciones: el caso de uso exacto para el que existe <dl>.

2. Estrategia CSS para la fluidez sin Media Queries

La restricción más exigente de la actividad es lograr adaptabilidad sin una sola regla @media. Se resolvió combinando cuatro técnicas de maquetación fluida clásica:

2.1 Anchos en porcentaje

Todo contenedor de layout (.contenedor, .tarjeta, .galeria__item) usa width en %, nunca en píxeles fijos. Así, cuando la ventana cambia de tamaño, cada elemento recalcula su ancho de forma continua y proporcional, sin "saltos" en puntos de quiebre fijos.

2.2 Float + clearfix

Las tarjetas de contenido y el glosario usan float: left para formar columnas. Como los elementos flotantes sacan a su contenedor del flujo normal (colapsando su altura), cada contenedor de columnas lleva la clase .clearfix, que aplica content: ""; display: table; clear: both; en un pseudo-elemento ::after para restaurar la altura correcta.

2.3 display: inline-block

La navegación y la galería de imágenes usan inline-block en vez de float: los elementos se comportan como palabras dentro de una línea de texto y se van solos a la línea siguiente cuando falta espacio horizontal, sin necesidad de detectar el ancho de pantalla con una Media Query.

2.4 max-width: 100% en multimedia

Toda imagen, iframe y video tiene max-width: 100% y height: auto, para que nunca desborden su contenedor, sin importar cuánto se achique la pantalla.

2.5 Proporción del video sin @media

El video propio usado en el sitio ya conoce su proporción real, así que le basta con max-width: 100% y height: auto para adaptarse. La clase modificadora .video-envoltorio--nativo desactiva el truco del punto siguiente para este caso. Ese truco ("padding-bottom": 56.25% = 9 ÷ 16, con el reproductor en position: absolute llenando el contenedor) se conserva en el CSS para la alternativa con <iframe> de YouTube, documentada como comentario en index.html, ya que un iframe no tiene una proporción propia y necesita que se la impongamos.

2.6 min-width como red de seguridad

En pantallas extremadamente angostas, un ancho puramente porcentual puede volver ilegible una tarjeta o una imagen. Se añadió un min-width discreto (por ejemplo, 220px) para evitar ese extremo; si el espacio es insuficiente, el navegador simplemente envuelve el elemento a la siguiente línea (gracias a float o inline-block), en vez de romper el diseño.

3. Cómo publicar el sitio (instrucciones sencillas)

Pasos básicos para completar los dos entregables pendientes de la actividad: el repositorio Git y el sitio publicado en línea.

Paso 1
Dentro de la carpeta IA y la comp acuantica/, abre una terminal y ejecuta: git init, luego git add . y git commit -m "Primer commit: estructura base del sitio".
Paso 2
Crea un repositorio nuevo y vacío en GitHub, copia la URL que te da (termina en .git) y ejecuta git remote add origin URL.
Paso 3
Sube los archivos con git push -u origin main (si tu rama se llama master, usa esa palabra en su lugar).
Paso 4
En GitHub, entra a Settings → Pages, elige la rama principal como fuente y guarda: GitHub te dará un enlace público donde el sitio queda desplegado.
